# RHEED MEF

面向 RHEED（反射高能电子衍射）成像的**相机响应标定 + 多曝光融合**工具。

RHEED 图像的动态范围极大：镜面衍射斑可以比背景亮几个数量级，任何单一曝光都无法同时把
斑点压在线性区、又把暗背景抬离噪声底。本项目先用多档曝光实测相机的非线性响应曲线，再用
这条曲线把各档图像换算到同一辐照度尺度上加权融合，得到一张既不过曝、也不丢暗部的图。

界面基于 PyQt6 / pyqtgraph，算法主体只依赖 NumPy / SciPy / OpenCV，可脱离相机离线运行与测试。

## 原理

### 1. 成像模型

相机输出的是**编码值** `Z`（Mono8 为 0–255，Mono12 为 0–4095），它由场景辐照度 `E` 和曝光
时间 `Δt` 共同决定，但中间隔着一个非线性函数 `f`：

```
Z = f(E · Δt)
```

`f` 里包含了传感器的线性响应、gamma 校正、增益、读出噪声和饱和。同一场景换一个曝光，`Z`
不再是线性缩放关系，所以**不能直接把多档图像按亮度相加**。

取反函数并取对数，定义

```
g(Z) = ln f⁻¹(Z)
```

则每一条观测都满足线性关系：

```
g(Z_ij) = ln E_i + ln Δt_j
```

其中 `i` 是像素、`j` 是曝光档。**未知量只有两样**：每个码值的 `g(Z)`，和每个像素的
`ln E_i`。这就是全部算法要解的东西。

### 2. 响应曲线求解（Debevec & Malik）

把所有像素 × 所有曝光的方程堆在一起，直接解是病态的：两端码值（接近黑、接近饱和）信噪比
很差，同时 `g` 和 `ln E` 之间差一个常数自由度。于是加两项约束——**权重**和**平滑**：

```
O = Σ_i Σ_j  w(Z_ij) · [ g(Z_ij) − ln E_i − ln Δt_j ]²
  + λ Σ_z    w(z) · [ g(z−1) − 2g(z) + g(z+1) ]²
```

**帽子权重**（对应 `hat_weights`）让两端不可靠的码值自动降权：

```
w(z) = z − Zmin              , z ≤ (Zmin+Zmax)/2
w(z) = Zmax − z              , z > (Zmin+Zmax)/2
```

两端权重趋近 0（饱和与噪声区不参与拟合），中灰处权重最大。

**平滑项**用二阶差分抑制噪声导致的曲线抖动；`λ` 默认 10。12 位图像码值更密，同一个对数
曲线的离散二阶差分天然更小，所以代码里把系数乘上 `码值个数 / 256`，让 12 位的 `λ=10` 与
8 位文献值处在同一工作点。

**锚定**：`g(Zmid) = 0` 用一行大权重（1e6）写进方程组，把整体尺度固定下来，否则解会整体
平移。

**求解**：未知量是 `n_codes + n_pix` 个，方程组是 `n_data + 1 + n_smooth` 行，用稀疏矩阵
装配后解正规方程。12 位时 `n_codes = 4096`，密集 SVD 会非常慢，所以先按列归一化再解，避免
条件数问题。实现见 `gsolve`，返回 `g` 和采样像素的 `ln E`。

**采样**：不需要用全部像素。`sample_pixels` 在码值上均匀铺开、在空间上尽量分散地取
（默认 200，标定时 4000）个像素，并避开 5×5 邻域方差高于 60 分位的像素（边缘、条纹处响应
不可靠），同时满足可解条件 `N·(P−1) > Zmax − Zmin`（`N` 为像素数，`P` 为曝光档数）。

**线性判定**：若标定出的 `g` 与理想直线 `ln(Z/Zmid)` 的均方根差不超过 0.05（且参与统计的
码值足够多），就判定相机在该配置下近似线性，直接换成解析直线 `choose_response`。这样避免用
一条几乎笔直的实测曲线把噪声也带进融合。

### 3. 多曝光融合

拿到 `g` 之后，每一档图像都能反解出辐照度：`ln E = g(Z) − ln Δt`。再用同一套帽子权重做
加权平均（对应 `merge_radiance`）：

```
            Σ_j w(Z_ij) · [ g(Z_ij) − ln Δt_j ]
ln E_i  =  ───────────────────────────────────────
                    Σ_j w(Z_ij)
```

于是亮部主要靠短曝光贡献（斑点不过曝），暗部主要靠长曝光贡献（背景离开噪声底），中间由
权重平滑过渡。若某像素在所有档的权重都是 0（全黑或全饱和），退化为取最接近中灰的那一档，
避免除零。

融合结果是**相对辐照度**（浮点，任意尺度），显示时对 `ln E` 取 1%–99.5% 分位窗口拉伸到
8 位，窗口只影响观感，不改变数值。

### 4. 曝光序列怎么排

固定一组曝光是浪费的：斑点先饱和，背景还远没到饱和。`exposure_plan.plan_bracket` 用探测帧
的实测结果排布：

1. 丢掉饱和像素比例超过 **10%** 的档（`SAT_LIMIT`），最长档上限 5 s（`MAX_EXPOSURE_US`）。
2. 用 99.99 分位峰值找**斑点档**：最长一档且峰值不超过满量程 85%（`PEAK_FRACTION`）的曝光，
   即斑点仍在直线区的最长曝光。
3. 斑点档及更短的档按 **2 倍**递进（`SHORT_RATIO`，默认补 2 档）——高光端变化陡，需要加密。
4. 斑点档以上按 **4 倍**拉开（`LONG_RATIO`）——长曝光只用来抬暗部，密度可以低。

这样同档数下，动态范围覆盖最宽，而融合权重在中灰附近交叠最多。

### 5. 流式增量融合

录像和实时预览不能每来一帧就重算全部曝光。`SlidingFusion` 把式 (6) 拆成每个档位各自的
分子、分母两张累加图：某一档换了新帧，只减掉旧的这一档、加上新的这一档，复杂度与档数无关。

改曝光后相机要过几帧才输出新曝光。`wait_settled` 要求**连续两帧整幅中位码值一致**
（相差 ≤15%），且该码值与本档曝光时间之比和其它已确认档位（比值差 1.5 倍以内）相符，才
收下这一帧；否则丢弃重来。中位数跟的是背景而不是少量斑点像素，因此对镜面斑不敏感。

### 6. 标定可靠性

`measure_response.py` 固定增益与 gamma，连拍两轮完整的已知曝光序列，检查三件事：

- 式 (2) 的加权残差是否小；
- 留出的曝光能否落在同一条曲线上；
- 两轮独立采集得到的 `g(Z)` 是否一致。

`calibration_plan.py` 负责多增益批量标定的档位与耗时估算：默认 7 个增益档
（2–32 档可调）、11 档几何曝光（500 µs … 512 ms）、2 轮重复。相机不报告增益步进时，用一次
中间值加二分查找读回差来推断步进（`infer_gain_increment`）。

### 7. 数值细节

- 码值范围按位深推断：`uint8` → 0–255；其余若峰值 ≤ 4095 按 Mono12 → 0–4095（`infer_code_range`）。
- 浮点图取整到整数码值再入算法（`_as_code_image`）。
- 曝光时间必须有限且为正；曲线长度必须与码值范围一致，否则直接报错而不是静默降级。
- 辐照度以 `float32` 返回，非有限值置 0。

## 相机与依赖

算法、规划、界面模块不需要相机即可运行和测试。相机采集模块（`camera_worker.py`、
`measure_response.py`、`probe_stream_rate.py`、`sliding_fusion.py` 的录像入口）在运行时把
上级目录加入 `sys.path` 并导入 `src.lib.VimbaX_camera`，即一个基于 Vimba X SDK 的相机封装；
这部分需要现场相机与 SDK 时才可用。

依赖见 `pyproject.toml`：`numpy`、`scipy`、`opencv-python`、`PyQt6`、`pyqtgraph`。
